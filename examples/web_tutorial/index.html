How this page works

This page is a tutorial and a terminal in one. Every step explains what a command does and why, runs the real command when you press its button, and shows the real output, just as a terminal would. Each card also shows the same command for your own terminal, so you can repeat everything without this page. The guide behind it is docs/HOW_TO.md.

Why there is a server, and what keeps it safe

Why a server
A web page can't run programs on your computer. examples/web_tutorial/server.py runs them for the page and sends back their output.
This machine only
It listens on 127.0.0.1, an address no other computer can reach.
Fixed commands only
It runs only the commands on this page. What you type (a question, an MFA code) is passed as data, never as a command, and is checked first.
Secrets stay hidden
AWS credentials, the client secret, the API key and access tokens stay in the server's memory. The page shows only their length, and output is scrubbed of them.
Nothing is saved
Stopping the server (Ctrl+C in its terminal) forgets everything it held. Your terminal's own AWS sign-in is not changed.
Cost
Sign-in and settings are free. Each model call costs a fraction of a US cent; the cost is printed with every answer.

Work through the steps in order: step 2 needs step 1, and steps 3-5 need step 2.

1. Sign in to AWS

AWS needs to know who you are before Terraform can read the connection settings in step 2. This step checks, or makes, a sign-in for each of the two profiles. Only the deploy profile is needed for the rest of the page; the review profile is here so you can see the difference.

Concepts

Profile
A named set of AWS CLI settings in ~/.aws/config. --profile powerlab-deploy tells a command which settings to use.
IAM role
A set of permissions you take on for a while, instead of having them permanently. Each profile here points at a role (role_arn).
Two roles, two jobs
powerlab-deploy can create and change this stack's resources. powerlab-review can only read, and is used for the Well-Architected review. Separate roles mean a review can never change anything (least privilege, Well-Architected SEC03-BP02).
MFA
Multi-factor authentication: a 6-digit code from an app on your phone, needed to take on either role. A stolen access key alone is not enough (SEC02-BP01).
Temporary credentials
Taking on a role returns credentials that expire after one hour. Nothing long-lived is handed out.
STS
AWS Security Token Service, which issues those temporary credentials and answers "who am I?".

3. Look inside an access token

Every API call starts by swapping the client ID and secret for an access token. The example clients do this for you; this step does it on its own so you can see what a token contains.

4. Prompt the model

Each example runs the real client from examples/. Every call goes through the API, so it gets the same checks, limits, cost estimate and logging as any other caller.

What happens on every call

1. Token
The client gets an access token from Cognito with the client ID and secret, and reuses it for 60 minutes.
2. API Gateway
Checks the token and its scope (else 401), the API key (else 403), and the rate limit and daily quota (else 429). Nothing has been paid for yet.
3. Lambda
The function checks the request body (else 400), turns the alias into the approved model, caps max_tokens, and calls Amazon Bedrock with the Converse API.
4. Bedrock
Runs the model through a tagged application inference profile, so its cost can be traced to this stack.
5. Response
The answer comes back with the tokens used and a cost estimate. The function logs one line of metadata: never the question or the answer.

5. What the API refuses

A secure API is defined as much by what it refuses as by what it answers. Each example sends a deliberately wrong request and shows the raw HTTP status and error. None of them reaches the model, so none of them costs anything.

6. Clean up

When you're done, forget what the page holds, then stop the server with Ctrl+C in the terminal where it runs. Stopping it forgets everything anyway.
